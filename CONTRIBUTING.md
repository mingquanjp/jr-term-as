# Contributing

## Branches

Use a short, descriptive branch name:

- `feat/<feature>` for a new capability
- `fix/<bug>` for a correction
- `chore/<maintenance>` for tooling or dependency work

## Pull requests

Please include:

- What changed and why.
- How the change was verified.
- Screenshots for meaningful UI changes.
- Any assumptions about the dictionary, transcript format or backend contract.

Keep pull requests focused. Do not commit internal JR source workbooks or raw meeting transcripts without explicit approval.

## Local checks

pnpm check
